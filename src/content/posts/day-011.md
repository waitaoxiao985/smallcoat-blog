> 主机发现告诉你「哪几台机器活着」，端口扫描才告诉你「每台机器开了什么服务」。这是侦察阶段信息密度最高的一步——一个版本号写错的服务，往往就是一个已知漏洞的入口。这篇从默认扫描一路做到 -sS -sV -O -p- 的综合扫描，把一台 Metasploitable2 靶机的底细摸干净。

## 一、扫描策略：从粗到细

端口扫描不能一上来就 -p- 全端口暴力跑，那样又慢又吵。正确的顺序是三层递进：

- 第一层：默认扫描。Nmap 只扫最常见的 1000 个端口，几秒钟出结果，先看大致有哪些服务。

- 第二层：全端口扫描。在确认目标值得深挖之后，-p- 扫 65535 个端口，找出藏在非标准端口上的服务。

- 第三层：定向深挖。对找到的端口逐个做 -sV 版本识别、-sC 默认脚本、-O 系统识别。

> **说明** 本文所有扫描针对自建 Metasploitable2 靶机 192.168.159.137，在隔离的 Host-Only 网络内完成。未对任何公网或未授权目标发起扫描。

## 二、默认扫描与指定端口

### 2.1　默认扫描

*默认扫描 1000 个常用端口*

```bash
nmap 192.168.159.137
```

不加任何参数，Nmap 扫最常见的 1000 个端口。这个默认值是统计出来的——覆盖了互联网上 90% 以上的实际服务。几秒钟出结果，适合快速摸底。

![图 1　默认扫描结果](/images/csdn/week02/Day011-1.png)

### 2.2　指定端口

*指定端口范围*

```bash
nmap -p 21,22,23,80,3306 192.168.159.137
nmap -p 1-1000 192.168.159.137
```

-p 后面可以是逗号分隔的列表，也可以是范围。已经知道目标类型（比如 Web 服务器）时，直接扫相关端口能省大量时间。

### 2.3　全端口扫描

*扫全部 65535 个端口*

```bash
sudo nmap -sS -p- -T4 192.168.159.137
```

-p- 等价于 -p 1-65535。这一步的意义在于：很多服务为了「安全」被挪到了高位端口（比如把 SSH 挪到 22222），默认扫描完全看不到。

代价是慢。65535 个端口即使加 -T4 也要几分钟，如果目标有防火墙丢包会更久。所以全端口扫描通常放在第二层，确认目标值得花这个时间之后再做。

## 三、-sS 与 -sT：两种扫描方式

TCP 端口扫描的核心区别在于「三次握手走到哪一步」。

| 参数 | 名称 | 握手过程 | 权限 | 特点 |
| --- | --- | --- | --- | --- |
| -sS | SYN 半开扫描 | 发 SYN，收到 SYN/ACK 就发 RST 断开 | 需要 root | 快、隐蔽，不建立完整连接，不会留在应用日志里 |
| -sT | 全连接扫描 | 完整三次握手后再断开 | 普通用户即可 | 慢、会被应用层记录，但兼容性最好 |

*两种扫描方式*

```bash
sudo nmap -sS 192.168.159.137
nmap -sT 192.168.159.137
```

为什么 -sS 更隐蔽？因为它不发最后的 ACK，连接从未真正建立，服务端的应用层根本不会收到「有人连上来了」这个事件，只有内核层记了一笔。而 -sT 走完整握手，Web 服务器、SSH 服务器的日志里都会留下访问记录。

![图 2　SYN 半开放扫描结果](/images/csdn/week02/Day011-2.png)

-sS 需要构造原始 TCP 包，所以必须 root。这也是为什么很多教程里的命令都带 sudo。

## 四、-sV：把端口变成版本号

知道 21 端口开着只是开始，知道它是 vsftpd 2.3.4 才是情报。这一步叫服务版本识别，靠的是向服务发探测包、分析返回的 banner 和响应特征。

*版本识别*

```bash
nmap -sV 192.168.159.137
nmap -sV --version-intensity 5 192.168.159.137
nmap -sV --version-all 192.168.159.137
```

--version-intensity 控制探测强度，1 到 9，默认 7。调低速度快但可能识别不出来，调高更准但更慢更吵。

如果版本显示为 unknown，直接上 --version-all，它会尝试所有探测探针，基本能压出结果。

![图 3　服务版本识别结果](/images/csdn/week02/Day011-3.png)

靶机识别出来的结果：vsftpd 2.3.4、OpenSSH 4.7p1、Apache httpd 2.2.8、Samba 3.0.20、MySQL 5.0.51a。这几个版本号每一个都对应着公开的漏洞记录——下一篇（漏洞初判）就是围绕它们展开的。

## 五、-O 与 -A：系统识别与全开

*操作系统识别*

```bash
sudo nmap -O 192.168.159.137
sudo nmap -A 192.168.159.137
```

-O 通过分析 TCP/IP 协议栈的指纹（初始序列号、TCP 选项、窗口大小等）猜测操作系统。-A 是 aggressive 的缩写，等价于 -sV -O -sC --traceroute 四合一：版本识别 + 系统识别 + 默认脚本 + 路由追踪。

靶机被识别为 Linux 2.6.x，与 Metasploitable2 基于 Ubuntu 8.04 的事实吻合。

![图 4　操作系统指纹识别结果](/images/csdn/week02/Day011-4.png)

-A 很方便但有代价：脚本会主动与服务交互，可能触发告警，也可能导致服务异常。生产环境慎用 -A，尤其不要对老旧服务跑 -sC，某些默认脚本会真的去「验证」漏洞。

## 六、综合扫描：一条命令拿全

*综合扫描*

```bash
sudo nmap -sS -sV -O -p- -T4 192.168.159.137 -oN full_scan.txt
```

把前面所有参数拼起来：SYN 半开扫描 + 全端口 + 版本识别 + 系统识别 + 加速 + 落盘。这是侦察阶段对单台主机的「最终扫描」，跑一次拿全所有信息。

![图 5　全端口综合扫描输出](/images/csdn/week02/Day011-5.png)

扫出 20 多个开放端口。除了常规的 21/22/23/25/80/139/445/3306，还有几个直接指向高危的：

| 端口 | 服务 | 版本 | 为什么高危 |
| --- | --- | --- | --- |
| 21/tcp | ftp | vsftpd 2.3.4 | 源码被植入后门，特定用户名可触发 root shell |
| 139/445 | smb | Samba 3.0.20 | usermap_script 远程命令执行（CVE-2007-2447） |
| 1524/tcp | bindshell | — | 直接监听一个 root shell，连上去就是 root |
| 3306/tcp | mysql | MySQL 5.0.51a | root 空口令，可直连数据库 |

## 七、踩坑记录

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| -p- 跑了很久没结果 | 65535 个端口逐个探测，默认时序太保守 | 加 -T4；或先扫 top 1000 确认值得深挖再全扫 |
| -sS 报权限错误 | SYN 扫描需要构造原始包 | 加 sudo |
| 所有端口都显示 filtered | 目标有防火墙丢包，或本机网络不通 | 换 -sT 试连通性，或加 -Pn 跳过主机发现 |
| 版本显示 unknown | 探测探针不够，或服务做了 banner 隐藏 | 加 --version-all 或 --version-intensity 9 |
| 扫描结果滚屏后找不到了 | 终端缓冲区有限 | 永远加 -oN 落盘 |

### 坑 1：-p- 扫到怀疑人生

第一次跑 sudo nmap -sS -p- 192.168.159.137，没有加 -T4，等了十几分钟还在跑。中途 Ctrl+C 了两次，都白跑了。

原因：65535 个端口，Nmap 默认对每个无响应端口都会等超时重传，局域网里虽然快，但累积起来仍然很可观。加 -T4 之后同样的扫描 2 分钟出结果。

更好的做法是分层：先 -p 21,22,23,80,3306 快速看常规端口，确认有货再上 -p- 全扫。别一上来就全端口。

### 坑 2：-sS 不加 sudo 报错

直接敲 nmap -sS，返回「You requested a scan type which requires root privileges」。

原因：-sS 需要自己构造 TCP 包（发 SYN、收 SYN/ACK、发 RST），这是 raw socket 操作，普通用户权限不够。同理 -O（系统识别）也需要 root，因为要读原始响应。

解决：加 sudo。或者改用 -sT（全连接扫描），普通用户就能跑，代价是慢且不隐蔽。

### 坑 3：所有端口都 filtered

有次扫描结果里每个端口都是 filtered，一个 open 都没有。第一反应是目标没开服务。

实际上 filtered 的意思是「没收到任何回应」——可能是防火墙 DROP，也可能是网络根本不通。判断方法：先用 -sT 试一次，如果 -sT 能扫出 open，说明是 -sS 的包被拦了；如果 -sT 也全 filtered，那就是网络层不通，回去查路由和网段。

另一个常见情况是主机发现被拦——目标不回应 ping，Nmap 就认为主机不在线，直接跳过。加 -Pn（跳过主机发现，强制扫描）可以绕过。

### 坑 4：版本识别出 unknown

-sV 扫出来一堆 unknown，只能看到端口开着但不知道是什么服务。

原因有两个：一是探测探针不够（默认强度 7 已经不错，但有些服务藏得深）；二是服务本身故意隐藏 banner。

解决：加 --version-all 让 Nmap 尝试全部探针，基本能压出结果。如果还是 unknown，就只能手工连上去看（nc 目标 端口 手动发命令看响应）。

### 坑 5：结果没落盘

扫了 20 多个端口，结果在终端里滚过去，往上翻只找到一半。想重新看某个端口的版本，只能重扫。

这是纯粹的习惯问题。所有扫描命令都应该带 -oN 输出到文件，-oA 更好（同时输出 txt/xml/gnmap 三种格式）。侦察阶段的每一条命令输出都是后续报告的证据，丢了就得重来。

## 八、小结

- 扫描顺序三层递进：默认 1000 端口摸底 → -p- 全端口找隐藏服务 → 对开放端口做 -sV/-sC 深挖。

- -sS 是 SYN 半开扫描，快且隐蔽，必须 root；-sT 是全连接扫描，普通用户可用但会留日志。

- -sV 把端口号变成版本号，这一步是后续查 CVE 的前提；unknown 就上 --version-all。

- -A = -sV -O -sC --traceroute，方便但会主动交互，生产环境慎用。

- 综合扫描一条命令：sudo nmap -sS -sV -O -p- -T4 目标 -oN 输出。

- 永远落盘。侦察结果就是报告的证据链，丢了要重扫。
