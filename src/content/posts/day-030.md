## 二、实操过程记录

### 阶段 1：知识体系自检（40 分钟）

按周把技能列出来，逐项打「熟练 / 一般 / 需复习」。自检的目的不是给自己打分，而是找出下一阶段要补的窟窿。

| 周次 | 核心技能 | 自评 | 备注 |
| --- | --- | --- | --- |
| Week 1 | Kali 环境、Burp 抓包、暴力破解、Wireshark、Hydra | 熟练 | Burp 代理配置踩过坑，已形成习惯 |
| Week 2 | Google Hacking、WHOIS/DNS、Nmap 主机与端口扫描、版本识别 | 熟练 | Nmap 参数需要常查手册 |
| Week 3 | 注入点判断、字符/数字型区分、Union 注入、SQLMap、哈希破解 | 熟练 | 数字型与字符型的区别能讲清 |
| Week 4 | 三种 XSS、XSS 绕过、文件上传、上传绕过、Webshell、蚁剑 | 熟练 | 存储型判断最花时间 |
| Week 5 | 综合渗透、报告编写 | 一般 | 第一次写正式报告，结构还要练 |

需要复习的三项：Nmap 的 NSE 脚本、哈希破解（hashcat 规则）、报告的风险定级标准。

熟练的标准我定成「不看笔记能独立做完并且能讲清为什么」，做不到就标「一般」。

### 阶段 2：报告结构设计（20 分钟）

报告分两拨读者：老板只看前两页（结论、风险、要花多少钱修），技术看中间（怎么复现、影响多大）。所以结构必须按「先结论后细节」排。

| 章节 | 读者 | 写什么 |
| --- | --- | --- |
| 1 执行摘要 | 老板 | 测了什么、发现几个洞、整体风险、一句话结论 |
| 2 测试范围 | 双方 | 目标 IP、端口、模块、时间、授权情况 |
| 3 测试方法 | 技术 | 用了哪些工具、按什么流程、什么级别 |
| 4 漏洞详情 | 技术 | 每个洞：位置 + 复现步骤 + 请求响应 + 影响 |
| 5 风险评估 | 老板 | 等级 + CVSS + 修复优先级 |
| 6 修复建议 | 技术 | 立即 / 短期 / 长期三档 |
| 7 附录 | 技术 | payload 清单、工具版本、截图索引 |

关键原则：漏洞详情必须能让另一个人照着复现。「上传成功」不算复现步骤，「Burp 把 Content-Type 改成 image/jpeg 后上传成功，路径是 …/uploads/shell.php」才算。

### 阶段 3：报告正文编写（90 分钟）

按 Day 029 的实测结果填写。数据脱敏：密码只保留前 8 位，靶场 IP 可以保留（内网自建）。

```text
# Week 5 渗透测试报告（节选）
## 1 执行摘要
本次对 DVWA 靶场（Medium）进行全流程渗透，共发现 4 个漏洞：
文件上传  严重  CVSS 9.8  可 GetShell，直接控制服务器
SQL 注入   高    CVSS 8.6  可拖库，泄露全部账号哈希
存储型 XSS 高    CVSS 7.5  影响所有访问留言板的用户
反射型 XSS 中    CVSS 6.1  需诱导点击，影响单个用户
攻击链：上传 Webshell → whoami 为 SYSTEM → 完全控制。
## 2 测试范围
目标 IP：192.168.1.101　端口：80/tcp（HTTP）
模块：SQL Injection / XSS / File Upload
安全级别：Medium　时间：2026-11-09　授权：本地自建靶场
## 3 漏洞详情（以文件上传为例）
风险等级：严重
位置：/dvwa/vulnerabilities/upload/　参数：uploaded
复现步骤：
1) 准备 shell.php：<?php @eval($_POST['cmd']); ?>
2) Burp 拦截上传请求，把 Content-Type 改为 image/jpeg
3) 放行，文件落到 /dvwa/hackable/uploads/shell.php
4) POST cmd=system('whoami')，返回 nt authority\system
影响：任意命令执行，服务器完全失陷。
修复：后缀白名单 + 重命名 + 上传目录禁止执行 + 校验真实文件内容。
```
四个漏洞的「复现步骤」都写成了可照做的编号列表，每条都带具体 payload 和回显。

风险定级参考 CVSS 3.1：文件上传拿 SYSTEM 给 9.8，SQL 注入能拖库给 8.6，存储型 XSS 影响所有访客给 7.5，反射型需诱导点击给 6.1。

### 阶段 4：修复建议与交付（30 分钟）

修复建议分三档，避免「全部推倒重写」这种没法落地的建议。

| 优先级 | 措施 | 对应漏洞 |
| --- | --- | --- |
| 立即（24h） | 禁用或严格校验上传功能；删除已上传的可疑文件；把 DVWA 移出生产环境 | 文件上传 |
| 短期（1 周） | 全部 SQL 改参数化查询；输出统一 HTML 实体编码；Cookie 加 HttpOnly | SQL 注入、XSS |
| 长期（1 月） | 数据库账号降权（去掉 FILE/DROP）；上传目录禁止执行；部署 WAF；建立安全开发规范 | 全部 |

交付物：phase1_pentest_report.docx（正文 8 页 + 附录截图 12 张）。

自查清单：执行摘要有、范围有、每个洞有复现步骤、有风险等级、有修复建议、附录有 payload 和截图索引——六项齐全才算合格。

## 三、实践心得

1. 写报告比打靶更暴露问题。打靶时我可以凭手感跳步，写报告时每一步都必须能解释，跳过的步骤立刻变成「复现不了」。

2. 报告的价值不在「发现了几个洞」，而在「让对方知道先修哪个」。按 CVSS 和利用难度排出优先级，比罗列一堆漏洞有用得多。

3. 第一阶段的真正产出不是技能清单，是一套固定流程：收集 → 判断 → 利用 → 记录 → 报告。流程跑顺了，换靶场只是换参数。

## 四、重点与难点

1. 必须记住的知识点

① 报告的六要素：执行摘要、测试范围、漏洞详情、风险评级、修复建议、附录。

② 漏洞详情四件套：位置 + 复现步骤 + 请求响应证据 + 影响。

③ CVSS 3.1 的三个维度：攻击向量、复杂度、影响（机密性/完整性/可用性）。

④ 修复建议必须分优先级，否则等于没给建议。

2. 踩过的坑

① 初稿只写「上传成功」，自己回看都复现不了，补上完整 Burp 请求后才合格。

② 风险等级一开始全写「高危」，没有区分度，按 CVSS 重排后才合理。

③ 截图没有编号，正文引用时对不上，后来统一改成「图 N + 表八索引」。

3. 需要补的课

① 补课：CVSS 3.1 计算器，把评分从拍脑袋改成可解释。

② 补课：报告模板的排版规范（目录、页眉、图表编号）。

③ 预习：Week 6 注入进阶（盲注、时间盲注、报错注入、WAF 绕过、二次注入）。

## 六、第一阶段总结

一个月，从「Burp 都打不开」到「能独立完成一次渗透并写出报告」。技能树长这样：信息收集（被动 + 主动）→ 漏洞利用（SQL 注入 / XSS / 文件上传）→ 后渗透（Webshell 管理 + 信息收集）。

三条最实在的结论：① 过滤不等于安全，只做一半的防护等于没做；② 顺序比技巧重要，渗透是流程不是连招；③ 报告才是交付物，「我进去了」不是。

第二阶段（Day 31-60）开始学「看不见回显怎么办」和「有防护怎么办」。挖洞的天花板，取决于绕过防护的能力。
