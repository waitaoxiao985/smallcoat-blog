> 暴力破解是入门阶段最有成就感的一课——写几十行脚本不如配好一个工具。这篇文章完整走一遍 Burp Intruder 的流程：抓请求、标位置、装字典、跑攻击、看结果。重点是第二节和第五节，90% 的失败都出在“攻击位置标错”和“结果判读错”这两步。

## 一、先搞清楚爆破什么

DVWA 左侧菜单里有一个 Brute Force 模块，页面长得和首页登录框几乎一样，但它不是首页那个登录。很多人第一次点进去，在首页登录框上折腾半天，其实靶子在另一个页面。

正确入口：登录 DVWA 后，点左侧 Brute Force，看到的才是本次的爆破目标。

> **注意** 爆破前请确认 DVWA 安全级别是 Low。在 impossible 级别下，DVWA 内置了失败次数限制和延时，字典跑完也出不来结果，会白白浪费一小时。

## 二、抓取登录请求

打开 Burp 的 Intercept is on，回到 Brute Force 页面，故意输入错误的凭据提交——用户名填 admin，密码填 wrongpassword。这里用错密码是有意的，方便后面定位 payload 位置。

请求被 Burp 拦下后，右键选择 Send to Intruder，然后点 Forward 放行。切到 Intruder 标签页，就能看到刚发过来的请求。

![图 1　右键 Send to Intruder 把请求送进爆破模块](/images/csdn/week01/Day004-1.png)

## 三、配置攻击位置（最容易出错的一步）

Intruder 的第一个标签就是 Positions。Burp 会自动尝试标记一些位置，但这些自动标记几乎总是错的，必须先全部清掉再手动标。

标准操作顺序：

*标记 payload 位置*

```text
1. 点右侧 Clear § 按钮 → 清除所有自动标记
2. 在请求体里，用鼠标只选中 wrongpassword 这 13 个字符
3. 点右侧 Add § 按钮 → 给它加上标记
4. 检查上方 Payload positions 的数字，必须是 1
```

标完之后请求体应该长这样：

*期望的标记结果*

```text
username=admin&password=§wrongpassword§
```

只有 §…§ 之间的内容会被字典替换，其余部分原样发送。所以 username=admin 保持不变，每次请求只换密码——这才是我们想要的爆破。

![图 2　Positions 标签页，Payload positions 显示为 1](/images/csdn/week01/Day004-2.png)

## 四、装字典

切到 Payloads 标签，Payload type 保持 Simple list，然后有两种装字典的方式。

### 4.1　方式一：手动输入几个

练手阶段用几个常见弱密码就够了。在 Payload Options 的输入框里一行一个填：

*手动字典*

```text
123456
password
admin
qwerty
12345678
```

注意每行一个，不要加逗号或空格，否则会把整行当成一个密码。

### 4.2　方式二：加载 Kali 自带字典

Kali 预装了著名的 rockyou 字典，先确认文件在不在：

*检查字典文件*

```bash
ls -lh /usr/share/wordlists/rockyou.txt
```

rockyou 有 1400 多万行，直接跑要很久。练习时先截取前 1000 行：

*截取字典*

```bash
head -1000 /usr/share/wordlists/rockyou.txt > ~/passwords.txt
wc -l ~/passwords.txt    # 确认是 1000 行
```

然后在 Payloads 标签点 Load… 选择 ~/passwords.txt 加载进来。

![图 3　Payloads 标签页加载字典文件](/images/csdn/week01/Day004-3.png)

## 五、跑攻击并判断结果

点右上角 Start attack。Community 版会弹窗提示限速，点 OK 继续。

攻击窗口里每一行就是一次尝试，主要看四列：

| 列 | 含义 | 怎么用 |
| --- | --- | --- |
| Payload | 本次用的密码 | 确认字典是否正确加载 |
| Status | HTTP 状态码 | 成功通常是 302 或 200 |
| Length | 响应长度 | 长度不同 = 响应内容不同 = 可能是成功 |
| Error | 错误信息 | 有报错说明请求本身有问题 |

最快的判断方法是点 Length 列标题排序。失败时服务器返回的页面长度都一样，只有成功那一次的响应长度会明显不同。

找到可疑行后双击它，在 Response 里看正文。成功的标志是页面里出现这句：

*成功标志*

```text
Welcome to the password protected area admin
```

本例最终跑出的密码是 password。

## 六、踩坑记录

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| Payload positions 不是 1（是 0 或 2+） | 标记错位或多标 | Clear 后重新只标密码值 |
| 跑完所有 Length 完全一样 | 标记错了，字典根本没生效 | 先怀疑标记，别怀疑字典 |
| 多个 Payload 的 Length 相同 | 响应长度偶然一致 | 双击看 Response 正文确认 |
| 找不到 rockyou.txt | 文件是 .gz 压缩包或路径不对 | gunzip 解压，或换字典路径 |
| 攻击跑得特别慢 | Community 版限速（官方设计） | 属正常现象，等或改用少量字典 |

### 坑 1：标记位置错了

这是最核心的坑，也是最难自查的。常见的两种错误：

- 标记框得太大，把 password= 这个前缀也框进去了。这样字典里的每个密码都会被拼成 password=123456 发出去，当然不可能成功。

- 标记了多个位置。比如把 username 的值也标上了，Burp 就会做笛卡尔积，请求数暴涨，而且用户名被换掉后登录逻辑完全不同。

自查方法：标完后盯着请求体看一遍，确认 §…§ 中间只有密码值，且只有一对。

### 坑 2：所有响应的 Length 一模一样

字典跑完，几百行的 Length 全是 1234，一个例外都没有。这时候不要怀疑字典不够好——几乎一定是标记错了，导致每次请求发的内容其实是一样的（或者密码位置没被替换）。

诊断顺序应该是：先看 Positions 是否正确 → 再看 Payloads 是否真的加载了内容 → 最后才怀疑字典。我当时在这个坑上耗了很久，一直在换字典，方向完全错了。

### 坑 3：多个结果 Length 相同，分不清哪个是真的

有时候会有两三个 Payload 的响应长度相同。原因是不同密码失败时，服务器返回的错误提示文案长度可能恰好一致。唯一可靠的办法是双击进去读 Response 正文，看有没有那句 Welcome。

### 坑 4：Community 版攻击速度很慢

Intruder 跑起来一秒一个请求，几百个密码要等很久。这不是配置问题，是 Burp Community 版官方做的限速。练习阶段用几十到几百个密码就够了，不要一上来就上百万级字典。

## 七、四种攻击模式对比

Intruder 的 Attack type 有四种，理解它们的差别能省很多时间：

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| Sniper | 单字典，逐个位置轮流替换 | 最常用，单参数爆破 |
| Battering ram | 单字典，所有位置同时填同一个值 | 用户名密码相同的场景 |
| Pitchfork | 多字典并行，一一对应 | 已知用户名密码配对关系 |
| Cluster bomb | 多字典全组合（笛卡尔积） | 用户名密码都要爆，量级大 |

## 八、附录：弱密码 Top 5

| 排名 | 密码 | 说明 |
| --- | --- | --- |
| 1 | 123456 | 常年第一，纯数字序列 |
| 2 | password | 英文单词，最经典的默认密码 |
| 3 | 12345678 | 在上面的基础上加两位 |
| 4 | qwerty | 键盘第一行，纯手指记忆 |
| 5 | 123456789 | 再长一点的数字序列 |

这五个密码覆盖了大量真实系统的弱口令。防御角度说一句：任何系统都应该强制密码复杂度并限制失败次数，这两条能挡住绝大多数暴力破解。

## 九、小结

- 爆破的目标是 DVWA 左侧的 Brute Force 模块，不是首页登录框。

- Positions 必须先 Clear 再手动标，Payload positions 必须等于 1。

- 结果判断靠 Length 排序，最终确认要双击看 Response 正文。

- 所有 Length 都一样时，先怀疑标记，不要急着换字典。
