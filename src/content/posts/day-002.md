> 有了 Kali 攻击机，下一步需要一个能合法练手的靶子。DVWA 是公认最好的 Web 安全入门靶场，但手工装 LAMP 环境太折腾。这篇文章用 Docker 把整套环境压缩成一条命令，并把从安装到数据库初始化过程中我踩到的四个坑逐条拆开——其中两个坑官方文档根本没提。

## 一、为什么用 Docker 跑靶场

DVWA（Damn Vulnerable Web Application）是一套故意写满漏洞的 PHP 应用，专门用来练习 SQL 注入、XSS、文件上传这些攻击手法。传统装法是搭 Apache + PHP + MySQL，环境依赖多、版本冲突多、卸载还卸不干净。

Docker 的思路完全不同：把应用连同它需要的运行环境一起打包成镜像，跑起来就是一个独立容器。对靶场来说好处很直接——起一条命令就有，删一条命令就没，不污染宿主机，重装系统也不用重配环境。

| 对比项 | 传统手工搭建 | Docker 方式 |
| --- | --- | --- |
| 安装耗时 | 1–2 小时，依赖多 | 约 3 分钟 |
| 环境隔离 | 与宿主机混在一起 | 容器独立，互不影响 |
| 卸载清理 | 残留配置难清干净 | 删容器即彻底清除 |
| 重装成本 | 要重新走一遍流程 | 一条命令重建 |

## 二、安装 Docker

在 Kali 终端里依次执行下面四条命令。Kali 的软件源里已经带了 docker.io 包，不需要额外加源。

*安装 Docker*

```bash
sudo apt update
sudo apt install -y docker.io
sudo systemctl start docker
sudo systemctl enable docker
```

最后验证一下版本，能打印出版本号就说明装好了：

*验证安装*

```bash
sudo docker --version
# 输出示例：Docker version 24.x.x, build xxxxxxx
```

## 三、启动 DVWA 容器

一条命令把镜像拉下来并跑起来，把容器的 80 端口映射到本机的 80 端口：

*启动 DVWA*

```bash
sudo docker run -d -p 80:80 vulnerables/web-dvwa
```

参数含义：-d 表示后台运行，-p 80:80 表示“宿主机端口:容器端口”，最后的 vulnerables/web-dvwa 是镜像名。首次执行会自动下载镜像，需要等一会儿。

确认容器状态：

*查看容器状态*

```bash
sudo docker ps
# 关注 STATUS 是否为 Up，PORTS 是否显示 0.0.0.0:80->80/tcp
```

![图 2　docker ps 显示容器状态 Up、端口映射正常](/images/csdn/week01/Day002-2.png)

## 四、初始化数据库并登录

浏览器打开 http://127.0.0.1 ，会看到 DVWA 的初始化页面。这一步很多人会卡住——页面底部有一个 Create / Reset Database 按钮，必须点它，DVWA 才会建表并写入初始数据。

点完之后会自动跳到登录页，默认凭据是：

*DVWA 默认凭据*

```text
用户名：admin
密码：  password
```

![图 3　DVWA 数据库初始化完成，跳转到登录页](/images/csdn/week01/Day002-3.png)

> **重要** 登录后第一件事是把安全级别从默认的 impossible 改成 Low。impossible 级别下所有漏洞都被修复了，你在上面做任何攻击都不会成功，会白白浪费大量时间排查“为什么打不进去”。

## 六、踩坑记录

| 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| permission denied while trying to connect to the Docker daemon socket | 当前用户不在 docker 组 | sudo usermod -aG docker $USER 后重新登录 |
| Bind for 0.0.0.0:80 failed: port is already allocated | 80 端口被其他程序占用 | 停掉占用进程，或改用 -p 8080:80 |
| 浏览器显示连接被拒绝，但容器是 Up | 端口映射不对或页面缓存 | 核对 PORTS 列，Ctrl+F5 强制刷新 |
| 点 Create/Reset Database 报错 | MySQL 尚未启动完成 | 等 30 秒重试，或进容器看日志 |

### 坑 1：permission denied 连接 Docker 守护进程

装完 Docker 直接执行 docker ps，报错：

*报错原文*

```text
permission denied while trying to connect to the Docker daemon socket
at unix:///var/run/docker.sock
```

原因很明确：Docker 守护进程的 socket 只有 root 和 docker 组成员能访问，而刚装好的系统里当前用户还不在这个组。解决办法是把自己加进 docker 组：

*修复方式*

```bash
sudo usermod -aG docker $USER
# 然后退出登录重新进入（或直接重启），让组权限生效
docker ps    # 这次不加 sudo 也能跑
```

注意：加组之后必须重新登录才生效，只开个新终端是不行的。这一点很容易被忽略，很多人加完组发现还是报错，就以为命令写错了。

### 坑 2：80 端口已被占用

启动容器时报：

*报错原文*

```bash
docker: Error response from daemon: driver failed programming external connectivity
on endpoint dvwa: Bind for 0.0.0.0:80 failed: port is already allocated.
```

意思是宿主机的 80 端口已经被别的程序占了。按下面顺序排查：

*排查端口占用*

```bash
# 1. 看是不是之前起过同款容器
sudo docker ps -a
sudo docker stop $(sudo docker ps -q)   # 停掉所有运行中的容器

# 2. 看 80 端口到底被谁占了
sudo ss -tulpn | grep :80
sudo lsof -i :80
```

如果占用者是系统自带的 Apache 或 Nginx，可以直接停掉；如果不想动它，就换个端口映射，把宿主机的 8080 映射到容器的 80：

*改用 8080 端口*

```bash
sudo docker run -d -p 8080:80 vulnerables/web-dvwa
# 之后访问 http://127.0.0.1:8080
```

### 坑 3：容器 Up 但页面打不开

docker ps 显示容器状态正常，浏览器却提示连接被拒绝。三个检查点：

- 看 PORTS 列是否真的是 0.0.0.0:80->80/tcp，如果显示的是 80/tcp 而没有箭头，说明没做端口映射；

- 确认访问的是 http 而不是 https，DVWA 容器默认没有配 TLS；

- 浏览器缓存了之前的失败页面，按 Ctrl+F5 强制刷新一次。

### 坑 4：数据库初始化失败

点 Create / Reset Database 后报数据库连接错误，或者页面空白。最常见的原因是容器刚起来，里面的 MySQL 还在初始化，DVWA 这时去连就连不上。等 30 秒再点一次通常就好了。

如果一直失败，进容器内部看日志：

*排查容器内部*

```bash
sudo docker logs <容器ID>          # 看启动日志
sudo docker exec -it <容器ID> bash # 进入容器
# 容器内可以检查 mysql 进程与数据目录
```

## 七、Docker 常用命令速查

| 命令 | 作用 |
| --- | --- |
| docker ps | 查看运行中的容器 |
| docker ps -a | 查看所有容器（含已停止） |
| docker images | 查看本地镜像 |
| docker run -d -p 80:80 镜像名 | 后台启动容器并做端口映射 |
| docker stop 容器ID | 停止容器 |
| docker start 容器ID | 启动已停止的容器 |
| docker rm 容器ID | 删除容器 |
| docker rmi 镜像ID | 删除镜像 |
| docker logs 容器ID | 查看容器日志 |
| docker exec -it 容器ID bash | 进入容器内部 |
| docker pull 镜像名 | 拉取镜像 |

## 八、小结

- Docker 让靶场变成“一次性用品”，起停删都在秒级，特别适合反复练习。

- 装完 Docker 第一件事是把自己加进 docker 组，否则每条命令都要 sudo。

- 端口冲突是最常见的启动失败原因，ss / lsof 两个命令足够定位。

- DVWA 登录后必须把安全级别改成 Low，否则漏洞是关着的，打了也没反应。
