> Burp Suite 是 Web 安全领域最核心的工具，几乎所有 Web 漏洞测试都从“抓到一个请求”开始。这篇文章讲清楚它到底在做什么（中间人代理）、两端怎么配、HTTPS 证书怎么装，最后完整拦下一个登录请求，让你亲眼看到用户名和密码在请求体里是明文的。

## 一、Burp 到底在做什么

很多人第一次用 Burp 会困惑：为什么配个代理就能看到密码？道理其实很简单——Burp 把自己插在浏览器和服务器之间，充当“中间人”。

*代理的本质*

```text
正常情况：  浏览器  ──────────────────►  服务器

用 Burp 后： 浏览器  ──►  Burp  ──►  服务器
                    （请求先到 Burp，Burp 可以看、可以改、可以放行或丢弃）
```

因为浏览器的所有请求都先交给 Burp，Burp 自然能看到请求里的每一个字节，包括明文密码。更关键的是它能“停住”请求让你修改——这是后面所有漏洞测试的基础能力。

## 二、启动 Burp Suite

Kali 已经预装了 Burp，终端直接敲 burpsuite 就能启动。启动后会出现一个项目选择窗口：

*项目类型选择*

```text
Temporary project   → 临时项目（不落盘，适合练习，本文选这个）
New project on disk → 新建磁盘项目（需要保存历史记录时用）
Open existing project → 打开已有项目
```

选 Temporary project → 点 Next → 选 Use Burp defaults（使用默认配置）→ Start Burp。

## 三、两端配代理

抓包要打通一条链路，两端都要配：Burp 侧负责监听，浏览器侧负责把流量交出去。

### 3.1　Burp 侧设置

打开 Proxy → Options（新版本在 Settings → Tools → Proxy），确认监听地址是：

*Burp 默认监听地址*

```text
127.0.0.1:8080
```

这个配置一般不用改，默认就是对的。它表示 Burp 在本机 8080 端口上等着接收请求。

### 3.2　浏览器侧设置

以 Firefox 为例，进入 设置 → 网络设置 → 手动配置代理：

*Firefox 代理配置*

```text
HTTP 代理： 127.0.0.1    端口：8080
并勾选：Also use this proxy for HTTPS（HTTPS 也走这个代理）
```

> **注意** 那个“HTTPS 也走代理”的勾必须打上。不勾的话，只有 http 请求会经过 Burp，https 请求直连服务器，你会以为 Burp 坏了。

![图 2　Firefox 手动配置代理为 127.0.0.1:8080](/images/csdn/week01/Day003-2.png)

## 四、验证链路是否打通

打开 Proxy → Intercept，确认 Intercept is on（拦截已开启），然后在浏览器访问 DVWA 的登录页。如果 Burp 的 Intercept 标签页里出现了请求，说明链路通了。

确认没问题后，点 Forward 把请求放行，让页面正常加载出来。

![图 3　Intercept 成功拦截到请求](/images/csdn/week01/Day003-3.png)

## 五、拦下一个登录请求，找到明文密码

保持 Intercept is on，在 DVWA 登录页输入 admin / password 并提交。这时浏览器会一直转圈——因为请求被 Burp 拦住了，还没发给服务器。

切到 Burp 的 Intercept 标签页，就能看到完整的请求原文：

*拦到的 POST 请求*

```text
POST /login.php HTTP/1.1
Host: 127.0.0.1
User-Agent: Mozilla/5.0 (X11; Linux x86_64; rv:115.0) Gecko/20100101 Firefox/115.0
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,*/*;q=0.8
Content-Type: application/x-www-form-urlencoded
Content-Length: 33
Cookie: PHPSESSID=xxxxxxxxxxxxxxxx; security=low
Connection: close

username=admin&password=password
```

重点看最后一行：username=admin&password=password。密码就是明文，没有任何加密。这就是 HTTP 协议最根本的问题——它不保护传输内容。

| 字段 | 含义 | 本例的值 |
| --- | --- | --- |
| 请求行 | 方法 + 路径 + 协议版本 | POST /login.php HTTP/1.1 |
| Host | 目标主机 | 127.0.0.1 |
| User-Agent | 浏览器标识 | Firefox/115.0 |
| Content-Type | 请求体格式 | application/x-www-form-urlencoded |
| Cookie | 会话标识 | PHPSESSID=…; security=low |
| 请求体 | 真正提交的数据 | username=admin&password=password |

### 5.1　Intercept 的四个按钮

| 按钮 | 作用 |
| --- | --- |
| Forward | 把当前请求放行，发给服务器 |
| Drop | 丢弃当前请求，服务器收不到 |
| Action | 对该请求做其他操作（如 Send to Repeater） |
| Intercept is on / off | 开关拦截功能 |

## 六、踩坑记录

### 坑 1：配了代理，但 Burp 里一个包都没有

这是最高频的问题，原因通常有两个：

- 系统代理和浏览器代理冲突。如果操作系统层面也配了代理（或开了 VPN / 代理软件），流量可能被系统代理先接走，根本到不了 Burp。解决方法是关掉系统代理，只保留浏览器的手动代理。

- Intercept 没开。Intercept is off 状态下请求会被 Burp 自动放行，虽然能在 HTTP history 里看到，但不会停在 Intercept 标签页，容易误判成“没抓到”。

### 坑 2：访问 HTTPS 网站报 SEC_ERROR_UNKNOWN_ISSUER

配好代理后访问 https 站点，浏览器红屏报错：

*报错原文*

```text
SEC_ERROR_UNKNOWN_ISSUER
您的连接不是私密连接
```

原因是 Burp 作为中间人，需要用自己签发的证书冒充目标网站，而浏览器不认识 Burp 这个“假 CA”。解决办法是把 Burp 的 CA 证书装进浏览器信任列表：

*安装 Burp CA 证书*

```text
1. 保持代理开启，浏览器访问 http://burp
2. 页面右上角点 CA Certificate，下载 cacert.der
3. Firefox：设置 → 隐私与安全 → 证书 → 查看证书 → 证书颁发机构 → 导入
4. 导入时勾选“信任由此 CA 标识的网站”
```

装完之后 https 站点就能正常访问，Burp 也能解密看到明文了。这一步是所有 HTTPS 测试的前提。

### 坑 3：只看到 GET，找不到 POST 请求

登录动作明明是 POST，但在 Burp 里翻来翻去找不到。两个原因：

- Intercept is on 没打开，请求被自动放行了，此时应该去 Proxy → HTTP history 里找；

- 在 HTTP history 里没加过滤条件，列表太长看漏了。用 Filter 输入 /login.php 或选 Method = POST 过滤一下。

## 七、附录：HTTP 状态码速查

| 状态码 | 含义 | 在渗透中的意义 |
| --- | --- | --- |
| 200 | 请求成功 | 正常返回，可能包含敏感数据 |
| 302 | 重定向 | 登录成功后常见，跳转到首页 |
| 403 | 禁止访问 | 权限不足，可能存在越权点 |
| 404 | 资源不存在 | 路径探测时用来判断目录是否存在 |
| 500 | 服务器内部错误 | 可能由注入 payload 触发，是重要线索 |

## 八、小结

- Burp 的本质是中间人代理，两端都要配：Burp 监听 8080，浏览器把流量指过去。

- 抓 HTTPS 必须装 CA 证书，否则浏览器直接报证书错误。

- “HTTPS 也走代理”这个勾必须打，否则只能抓到 http 流量。

- 抓不到包先查三件事：系统代理是否冲突、Intercept 是否开启、过滤条件是否太窄。
